# Android build guide

The mobile app is an Expo SDK 54 / React Native 0.81 application. The source
is managed by Expo; `apps/mobile/android/` is generated by `expo prebuild` and
is intentionally gitignored.

There are two supported build paths:

| Goal | Path | Signing |
|---|---|---|
| Install a test build on a phone | Local debug APK | Android debug key; no private release key needed |
| Share, update, or publish the app | EAS preview/production | Must use the existing release keystore |

## Local debug APK

Install these prerequisites first:

- JDK 17.
- Android Studio or Android command-line tools.
- Android SDK Platform 35.
- Android SDK Build-Tools 35.0.0.
- Gradle network access to `services.gradle.org` and Google Maven on the first build.

On Windows PowerShell, the usual SDK setup is:

```powershell
$env:ANDROID_SDK_ROOT = "$env:LOCALAPPDATA\Android\Sdk"
$env:Path += ";$env:ANDROID_SDK_ROOT\platform-tools;$env:ANDROID_SDK_ROOT\cmdline-tools\latest\bin"
```

From the repository root:

```bash
pnpm install --frozen-lockfile
pnpm android:debug
```

The script regenerates the native project, runs the real Gradle build, and
prints the APK path:

```text
apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

With a connected phone and USB debugging enabled, install it with:

```bash
adb install -r apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

To generate only the native project without compiling it:

```bash
pnpm android:prebuild
```

The local script intentionally produces a debug APK only. It refuses to imply
that a debug-signed APK is a valid Play Store release or an update over the
existing production app.

## Signed APK through EAS

Use this path for a real shareable APK or an update to the existing app. The
repository already contains `.github/workflows/mobile-eas.yml`, which stages
the old signing key and runs the `preview` profile for an APK or the
`production` profile for an AAB.

Add these GitHub Actions secrets to the repository before dispatching the
workflow:

- `EXPO_TOKEN`
- `ANDROID_KEYSTORE_B64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_PASSWORD`

Never paste these values into chat or commit them. The keystore must be the
same key that signed the existing `com.hybridengine.app` installation. A new
key creates a different Android signing identity: the APK will not update the
old app and Google Play will reject it as an update.

Then open GitHub Actions → **Mobile — EAS Android build** → **Run workflow**
and choose:

- `preview` for a downloadable APK;
- `production` for a Play Store AAB.

The EAS build page provides the artifact download link after the build
finishes. The workflow also guards the package ID and versionCode so a build
cannot silently become a second Strength app.

## Conditioning Android build

Conditioning is a separate product identity. Its preview/production profiles
set `EXPO_PUBLIC_HYBRID_PRODUCT=conditioning` and use
`com.hybridengine.conditioning`. Before building it, create/link a separate EAS
project and supply:

- `EXPO_PUBLIC_CONDITIONING_EAS_PROJECT_ID`;
- `GOOGLE_MAPS_API_KEY` as an EAS/GitHub secret if route maps are required;
- a signing key appropriate for that separate Android package.

Do not reuse the Strength package ID or silently reuse its signing key for a
publicly separate product without deciding how Play Store identity should work.

## Why a build may fail in this workspace

The repository can be typechecked, Metro-bundled, and prebuilt without an
Android SDK. Native APK compilation cannot: Gradle needs the Android SDK and
its own distribution download. This container currently has Java 17 but no
Android SDK, `adb`, or network route to `services.gradle.org`, so the local
debug command is prepared but cannot finish here until those prerequisites are
provided. EAS moves native compilation to Expo's build machines and is the
shortest route when the required secrets are available.
